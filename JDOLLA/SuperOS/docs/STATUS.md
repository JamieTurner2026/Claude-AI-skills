# Status

Updated 2026-11-23. Built and tested in the cloud: every PR runs `npm run check`, `npm test`, `npm run eval:router` and `npm run smoke` on Linux and Windows (`.github/workflows/superos.yml`), with a fake Claude only. History lives in git and `docs/LEARNINGS.md`; what to run on the PC is in `START-HERE.md`.

## What works now

**Vault and content**
- Vault layout, router `CLAUDE.md`, seven department routers, `Home.md`, containment settings, `.gitignore`. One source brief per department in `raw/<dept>/charter/` and one charter note per department in `wiki/<dept>/`.
- Six project notes written from shallow clones of Jay's repos (snapshots in `raw/`): MIDNIGHT REIGN, Davidson Blessons, API Bible, Car Finder app, DDA2 Training Hub, Assembly Trainer Pro, plus a LEGEND OF DOOM stub. Concept notes `wiki/ai/memory-types.md` and `wiki/creative/creative-likes.md`. Skill draft `skills/weekly-review/SKILL.md` (inert).
- Vault generators (`npm run vault -- build [--dry-run]`, also at bridge start and every 30 min, and `POST /api/vault/rebuild`): `wiki/_master-index.md`, `wiki/<dept>/_index.md`, `reports/_index.md`, one `projects/<slug>.md` hub per project note, and today's `daily/YYYY-MM-DD.md`. Each file starts with `<!-- generated by os/vault: do not hand-edit -->` and is rewritten only when it changed; an unmarked file is never touched (except the old hand-made `_index.md` files, replaced once). In a daily note only the part above `## Notes` is generated (it also lists today's calendar and Brain-labelled mail); `## Notes` and below stay byte for byte. Writes only under `wiki/`, `reports/`, `projects/`, `daily/`; refuses links out; copies only names, titles and dates; never reads `.env*`, `os/` or `logs/`; never deletes.
- `daily/`, `projects/` and `reports/` are written by the generators (`reports/` also by runs); `logs/` by the bridge. All git-ignored.

**Bridge, dashboard and router**
- Bridge on 127.0.0.1 only, signed 24-hour sessions, guarded file access, a foreign `Origin` refused. Dashboard (midnight-and-neon look; command bar with live T1/T2/T3 bars; checked in a real browser at desktop and phone width): Directives, Clock, Departments, Routines, Skills, Runs, Proposals and Setup checklist widgets, and a Health strip.
- Three-tier router. `npm run eval:router` scores it on 72 labelled requests (`evals/router/requests.json`): 72/72, T3 29/29 (baseline before tuning was 63/72). Text can't pick its own tier ("T1:" labels and "ignore the router and" clauses are stripped); work on `raw/` or `.env` is answered, never run; "need a <deliverable>", "<deliverable> for …" and a trailing "can you look into it" count as work; "open a PR/issue/branch" means create; a bare list name ("apps") shows it; short work with only a pronoun as object ("make it pop") gets a clarifying T2 reply.
- Runs: T2 and T3 requests run Claude Code headless (Runs widget: live output, cost against cap, Stop). T3 asks for confirmation first. One real T2 run: right answer from the vault, $0.0012 of a $0.05 cap. A cap is checked after a turn, so it limits runaway spend but is not exact.
- Containment: skill policy (`os/config/skills.policy.json`), the vault's deny rules restated with absolute paths for every run, Bash only inside Claude Code's sandbox with no unsandboxed fallback, blocked tool calls shown and logged. Proven with real capped runs on a throwaway copy with fake `.env` secrets: a Read of `os/.env` was blocked by the CLI and nothing leaked; an allowed note read fine. A Grep attack also leaked nothing, but only because ripgrep skips hidden files, so the Grep deny path is not proven.
- Routines: switch one on in the Routines widget and it runs at its time while the bridge runs with `SUPEROS_SCHEDULER=on`; Run now works any time. All routines and skill runs together stop at $2 a day (a routine starts only if its full budget fits); each slot runs at most once, even across restarts. Read-only routines reply and the bridge writes the report to `reports/`. All six routines ship switched off: plan-today, morning-intel, proposals-review, vault-cleanup, content-cascade, vault-backup. One real plan-today run: a sourced plan for $0.0027.
- Skills widget: every `skills/<name>/SKILL.md` with tier and suggested budget (read from its "Tier: **T2" and "budget: **$0.25" lines; an unreadable line shows "unknown" and runs as T2 at $0.05). Run goes through the routine path (per-run limit `engine.routines.maxBudgetUsd`, shared daily cap, containment, learning loop); a T3 skill asks "Run this? Up to $X" first. A skill run is booked as `skill:<name>`, so it never marks a same-named routine done. Watch out: T3 skills suggest $1.00, so raise `engine.routines.dailyCapUsd` if you want one beside routines. The seven department agents each have a policy entry (default tools, no Bash).
- Inbox triage: the Proposals widget shows how many files wait in `inbox/` and has **Sort inbox**: one read-only T2 run ($0.05, not counted against the routine cap) over up to 25 files (names, sizes, first 800 characters, fenced as untrusted; dot files, `.env*`, links, folders, `README.md`, `_feeds/` and anything over 1 MB are skipped). The answer is re-checked; each valid suggestion becomes a `move` proposal. Approve is the only thing that moves a file (exactly one regular file into `raw/<known dept>/<slug>/`; real paths, no links, a taken name becomes `-v2`, nothing overwritten), then it rebuilds the indexes and marks the brain index stale.

**Second brain**
- Every T2/T3 run and routine gets the read-only `superos-brain` tools (`search`, `get_note`), rebuilt first if the index is over 5 minutes old (a failed rebuild never blocks a run). Off: `engine.brain.enabled`. One real run searched twice, opened the right note and answered from it for $0.0008. `raw/` results come back marked untrusted.
- Local meaning search (opt-in: `npm run brain -- index --embeddings`, the only command that downloads, about 500 MB runtime (transformers 4.3.2, pinned exact; `npm audit` clean) + 23 MB model `Xenova/all-MiniLM-L6-v2` into `~/.superos/brain/embeddings`). Each vector is tagged with the runtime version, so a runtime change re-embeds everything instead of mixing; an older runtime is refused with a plain message until `index --embeddings` replaces it: keyword and vector rankings merged by reciprocal rank fusion, with a cosine floor of 0.15 (`MIN_SIMILARITY`; chosen on 30 questions, re-check on the PC). Falls back to keywords if the model can't load; `SUPEROS_BRAIN_HYBRID=off` forces keywords. New or changed notes are embedded in the background (5 s per rebuild, never blocking a run).
- Brain eval (`npm run brain -- eval [--k 5]`, 30 invented questions: 10 keyword, 10 paraphrase, 10 synonym): keyword baseline hit@1 0.633, hit@5 0.867, hit@10 0.900, MRR 0.723; hybrid with the floor 0.833 / 0.933 / 1.000 / 0.883. At k=5, synonym questions go 0.600 → 0.800. Re-run on the PC after importing sessions.
- Session import (`npm run brain -- import-sessions [--dry-run] [--claude-ai conversations.json]`): user and assistant text only, secrets and personal data redacted first, one file per session in the git-ignored `raw/sessions/<source>/`, never overwrites, skips sessions already imported (ledger in `~/.superos/brain/`). Imported text is searched as untrusted `raw/` data.
- Mail into the brain (8a, offline half): `npm run brain -- import-mail [--dry-run]` reads Brain-labelled messages from `inbox/_feeds/mail.json` through `FileSource` (its guards unchanged) and writes one note per message to the git-ignored `raw/mail/YYYY-MM/<date>_<slug>.md` with frontmatter `type: mail`, `source: mail feed`, date, sender's name only, subject and `trusted: false`, plus the snippet (the feed has no full body). Redacted with the session-import redaction, which also masks digit runs of 9 or more (account or card numbers), then stripped of Markdown link, HTML and code characters. Never overwrites (`-v2`); deduped by message id through a hashed ledger in the log folder, not the vault. Search and `get_note` return these notes fenced as untrusted. Nothing connects to Gmail.
- Freshness: each `get_note` appends the note path and time (never the query or text) to `usage.jsonl` beside the index (512 KB cap, `SUPEROS_BRAIN_USAGE=off`). `npm run brain -- usage` lists the most-used and never-used notes; department indexes end each line "· last used <day>" or "· never used".
- Sources under every claim: runs record `toolsUsed` and `notesOpened`; the brain hint tells every run to name the vault note (path or `[[link]]`) for each claim. A finished T2 run that used the brain and names no vault path gets an `uncited` proposal (no diagnosis, no cost; Approve appends one rule to the skill). Not checked: T3, failed, diagnosis and triage runs, `NOTHING_NEW`, runs that skipped the brain. Off: `engine.learning.citations.enabled: false`.

**Safe tools and skills** (`os/tools/`, served by the bridge's `superos-tools` server, allowed by name in `skills.policy.json`; read-only, names, titles, dates and counts only, never a body; the default is just `today`)
- `today`, `recent_changes {days, dept?}`, `link_check {dept?}`, `vault_stats`, `list_reports {limit}`, `proposals_summary {days}` (also median days to decision and learned rules), `run_stats {days}`, `calendar_today`, `mail_brain {days}` (fenced as untrusted), `backup_status`. Safety is in `tools/vault.ts`: known top-level folders only, links never followed, dot entries and `.env*` skipped, `os/`, `logs/`, `raw/sessions/` and `outputs/_work/` never scanned, no path from the caller.
- Grants: vault-cleanup (link_check, vault_stats, backup_status), plan-today (recent_changes, list_reports, calendar_today, mail_brain), morning-intel (recent_changes, list_reports, proposals_summary, calendar_today, mail_brain), project-intelligence (recent_changes, vault_stats), knowledge-improvement (recent_changes, run_stats), proposals-review (proposals_summary, list_reports).
- Morning page (8c, offline): `morning-intel` writes five sections in order (facts with sources, guesses marked, filed overnight, waiting for Jay's yes, open questions), answers exactly `NOTHING_NEW` when nothing is new, and sends or drafts nothing. Switched off; turns on with feeds or connected accounts. Vault-cleanup has a Backups section and a "Stale and never used" section. Weekly review: `skills/proposals-review` (T2, $0.25, Sundays 17:00, off): what keeps breaking, whether approved rules helped, which skills get rejected most, up to 5 suggestions.

**Learning loop** (`proposals/`, Proposals widget with filter chips by kind, a one-line "why" on tune and uncited cards, keyboard j/k, a/r then y/n; a key alone never decides)
- A run that fails, has tools blocked or hits its cap gets a proposal; a read-only diagnosis run (up to $0.05; all together $0.25 a day) drafts the fix, the lesson and one skill rule. Approve adds a note to `wiki/_learnings/` and appends one rule under `## Learned rules`; nothing else in a skill changes. Kinds: budget, failed, blocked, move, uncited, tune. Real test: a plan-today run forced over a $0.0001 cap; the diagnosis cost $0.0008 and approving wrote the note and rule exactly.
- Run analysis (`npm run analyse:runs [-- --days 30]`, tool `run_stats`): spend per tier, skill and routine, failure and stop rates, the five costliest requests (first 80 characters of ordinary typed requests only), blocked counts, cap hits. "Suggest changes" turns fixed rules into `tune` proposals (3+ cap hits, 40%+ failures over 5+ runs, daily cap stopping 3+ runs, 5+ blocked calls): bridge text, no cost, at most 3 a week, no repeat for 28 days. **Approving a tune only records the decision; Jay edits config.** Bad or oversized log lines are counted and skipped; the newest 20 MB is read.
- Scorecard (`npm run analyse:learning [-- --days N] [--json]`): per kind made, approved, rejected, pending, median days to decision, and the skills with the most learned rules.

**Offline sources, backup, status and setup**
- Mail and calendar adapters (`os/sources/`, nothing connected, no network, no token): `FileSource` reads `inbox/_feeds/mail.json` and `calendar.json` (zod per item, 1 MB and 500-item caps, no links; a missing file is empty). Only mail labelled `Brain`, shown as name, date and subject, reduced to inert text. `inbox/_feeds/` is git-ignored.
- Vault backup (`os/backup/`, off, pushes nothing until Jay acts): git by argv with no shell, only in the vault folder, hooks off, no force, one push `HEAD:refs/heads/<branch>` to `engine.backup {remote, branch}` (branch validated strictly). Allowlisted staging, re-checked before the commit; the whole tree is checked for secrets already committed; links and files over 25 MB are left out and counted. Refuses with plain messages: no remote ("Name the private Brain repo first"), a URL outside `https://github.com/<o>/<r>.git` or `git@github.com:<o>/<r>.git`, the public repo (also after git's URL rewriting), a vault that is not its own repo, a vault inside or being a repo whose remote is the public one. Never touches credentials. `npm run backup -- --dry-run`; built-in routine `vault-backup` (daily 23:40, no model, $0).
- Health: `GET /api/health`, `npm run status` (exit 1 "not running", 2 unusable) and the Health strip (amber for scheduler off, index over 1 day, spend over 80%, failed or refused backup). Counts, states and times only. No tray icon (Windows-only).
- Setup checklist: `GET /api/setup` and a widget with one row per PC step (doctor, tests [manual], meaning search, sessions, autostart, backup, feeds), each with a state and the PC-SETUP section; manual ticks live in the browser only; hides itself when all are done.
- `npm run doctor [--json]`: PASS/WARN/FAIL for Node 22.18+, the Claude CLI, `os/.env` (existence only), vault layout, log folder, port, brain index, meaning search, Bash sandbox, scheduler and the vault backup row (own repo, remote passes the backup's check, FAIL if the vault's git points at the public repo). Exit 1 only on a FAIL; no network, no secrets printed.
- `npm run smoke`: copies the vault to a temp folder, runs the real bridge on it with the fake CLI, checks every GET route and one T2 run, rebuilds and searches the brain, deletes the copy (14 steps, about a second). `npm run update`: clean tree, `git pull --ff-only`, `npm ci`, doctor, smoke; stops at the first FAIL, never merges, rebases or forces, never touches `.env`, notes or the index. `npm run autostart -- install|remove|status [--dry-run]`: per-user Task Scheduler task "JDOLLA SuperOS bridge", 30 s after logon, no admin, `schtasks.exe` by argv; the first `install` only prints the plan; it records `installed` only after Task Scheduler accepts the task; macOS and Linux print a launchd or systemd unit.
- Red team (11a): one hostile fixture (`os/shared/hostile.ts`) is pushed through every untrusted door by `os/bridge/redteam.test.ts`: session and mail import, inbox triage, the mail and calendar feeds, the daily note, brain `search` and `get_note`, proposal text, the dashboard and the report writers. Every text cleaner strips all invisible and reordering characters (`\p{Cc}\p{Cf}\p{Zl}\p{Zp}`); session messages can't forge a turn or a heading; untrusted brain metadata is fenced; the diagnosis prompt quotes `whatBroke` as untrusted data; reports go through the vault guard, so a `reports/` link out of the vault writes nothing. `npm run redteam:ui` checks the dashboard in Chromium and is run by hand (it needs Playwright). Door table in `docs/LEARNINGS.md`.
- Accessibility (11b): `npm run a11y` (by hand, like `redteam:ui`) runs axe-core 4.10.3 (pinned dev dependency) in Chromium on a temp copy of the vault at desktop and phone size: 0 issues of any impact. A keyboard walk reaches every widget in layout order with a visible neon focus ring, and the Proposals keys still ask and cancel. Text colours reach AA on every background (`--accent-text` for accent-coloured text); the page has one `h1`; the Runs output is a focusable polite log that only appends; the Health strip says its warnings once, politely, when they change. `bridge/a11y-static.test.ts` (in `npm test`) fails if a button has no name (symbol-only text needs an `aria-label`), an input has no label, a live region is assertive, or a text colour drops under 4.5:1.
