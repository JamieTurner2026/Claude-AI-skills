# AI Research, Memory & Automation: department brief (source)

Source: Jay's interview answer, 2026-11-13. Jay's own text, lightly trimmed. Do not edit; append only.

Role: Chief AI Scientist, Memory Architect, and Automation Director

## What I would teach this department
- AI systems: language models, agents, tool calling, prompt engineering, and AI evaluations.
- Persistent memory: store project history, verified solutions, design decisions, and reusable lessons.
- Knowledge retrieval: RAG, embeddings, vector databases, semantic search, and source citations.
- MCP integration: connect Claude to supported tools such as GitHub, Blender, and other applications.
- Automation: workflows that execute repeatable tasks with appropriate permissions.
- Knowledge processing: analyze documentation, code repositories, transcripts, tutorials, and research materials.
- Quality control: identify outdated information, contradictions, unreliable sources, and hallucinations.

## How it would work
Six memory types: Project (what was built and why), Technical (verified code and fixes), Creative (approved artistic styles), Learning (concepts and exercises), Decision (choices and reasoning), Research (sources and findings). Example: extract the useful knowledge from a programming tutorial, organize it by topic, check important claims, and retrieve it later when a build needs the same technique.

## Advanced feature
A Knowledge Improvement Engine that evaluates new information and recommends updates to existing skills. It does not retrain the model; it improves instructions, retrieval and tools.
